# 评测与实验计划

## 指标（Metrics）
- 性能：吞吐（RPS）、延迟（p50/p95/p99）、错误率、并发连接数
- 资源：CPU、内存、网络、磁盘 IO
- 缓存：命中率、回源比例、热点 Key 访问分布
- 业务：发布成功率、计数一致性差异（Redis vs MySQL）

## 场景（Scenarios）
1. 读多写少：Feed 拉取
2. 写多读多：点赞/取消点赞“抖动”场景
3. 大对象写：分片上传 + 合并
4. 关系强交互：关注/取关 + 关注流拉取
5. 故障注入：MQ 暂停、Redis 宕机、MySQL 延迟升高

## 方法（Methodology）
- 压测工具：
  - 推荐 vegeta 或 k6；也可使用 wrk（HTTP 侧）。
- 步骤：
  1. 使用 Docker Compose 启动依赖与服务；
  2. 预热数据（生成用户/视频/关系）；
  3. 分阶段升压（线性到峰值），记录指标；
  4. 注入故障，观察重试与 DLQ；
  5. 导出 Jaeger 链路数据与日志进行分析。

## 验收门槛（示例）
- Feed p95 < 80ms（缓存命中）；发布成功率 > 99.9%；
- 点赞/取消点赞在 2000 RPS 下 p95 < 120ms，计数偏差 < 0.5%；
- 故障注入后系统在 1 分钟内自愈（队列积压可控，DLQ < 阈值）。
